# Chosen article:

[Managing the Consequences of Technical Debt: 5 Stories from the Field](https://www.sei.cmu.edu/blog/managing-the-consequences-of-technical-debt-5-stories-from-the-field/)

I find the article interesting because I feel like, especially in practical courses, the scalability/sustainability aspect of code or best practices when it comes to large-scale projects is overlooked. We don't really study or feel the consequences when we choose an easy, 'band-aid' fix for a problem and it's really interesting to see how big of an issue poor planning and laziness can become, especially because I've always been told if it's not incredibly inefficient it's probably okay.

# Aashma's Thoughts

I never knew about the term technical debt before I read this article. It was something I knew the concept of, but I didn't know there was a word for it.
